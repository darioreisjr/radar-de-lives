# Radar de Lives — orientações para agentes

- Processo obrigatório: skill SDD em `.claude/skills/sdd/SKILL.md`. Cada fatia tem `docs/specs/<id>-<slug>/{spec,plan,tasks}.md`.
- Fonte de requisitos: `docs/product/PRD_Radar_de_Lives_GTA6.md` (com o adendo multiplataforma, seção 12). Não invente requisitos. Plano e portões da multiplataforma: `docs/plans/multiplataforma.md`.
- Next.js 16.4 com `cacheComponents: true`. Antes de usar APIs do Next, leia a doc embutida em `node_modules/next/dist/docs/`.
- npm é o gerenciador. Verificações: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`.
- `npm test` usa `scripts/test.mjs` para normalizar a letra do drive no Windows (Vitest quebra com `d:` vs `D:`).
- **Plataformas:** YouTube, Twitch e Kick em produção. `LIVES_PROVIDERS` (padrão `youtube`) escolhe as ativas e a ordem de intercalação; uma plataforma sem credenciais fica de fora sem quebrar o site. A lista é lida no build e no servidor: mudar a variável na Vercel exige redeploy. Desligar = tirar da lista + redeploy.
- **Segredos só no servidor** (`lib/config/server-env.ts`, `import "server-only"`, nunca `NEXT_PUBLIC_`): `YOUTUBE_API_KEY`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `KICK_CLIENT_ID`, `KICK_CLIENT_SECRET`. Os tokens de app da Twitch e da Kick ficam só em memória. A resposta de canais da Kick traz `stream.key`/`stream.url` do streamer: o schema nunca os lê. Nunca logar URLs do YouTube (contêm a chave) nem tokens. O CI falha se o bundle do cliente tiver o endpoint de token ou o nome das credenciais da Twitch ou da Kick.
- **Nova plataforma:** implemente `LivesProvider` (`lib/lives/providers/types.ts`) com cache e single-flight próprios, registre em `lib/lives/server.ts` e no mapa `lib/lives/platforms.ts` (rótulos com gênero, player, consentimento, tamanho mínimo, aviso de login). Textos do site vêm de `lib/lives/copy.ts`; não espalhe nomes de plataforma pela UI.
- **Identidade:** `id = <plataforma>:<sourceId>` (`lib/lives/identity.ts`); deduplique por `id`. `videoId` saiu do payload público (spec 053) e só existe dentro de `lib/youtube`; `withIdentity` normaliza itens do cache em formatos antigos (preenche `id` e remove `videoId`). Mudar o formato de item em cache exige teste com cache no formato antigo (incidente de 2026-11-25).
- **Rotas:** `GET /api/lives` (com `sources` por plataforma) e `GET /api/status/[platform]/[id]` (revalidação ao abrir o player, cache de 60 s). A antiga `/api/lives/[videoId]` foi removida (spec 053). Dados simulados de desenvolvimento são marcados com `demo: true`, montado só no cliente.
- Estado compartilhado (spec 005): `lib/store` escolhe Upstash (se `UPSTASH_REDIS_REST_*`/`KV_REST_API_*`) ou memória. Falhas do store fecham para as APIs externas e abrem para o rate limit. Nunca gravar IP em claro no store. Preview e Development usam prefixo próprio nas chaves (`preview:`, `development:`); Production usa as chaves de sempre (spec 036). Não mude chaves de Production sem plano de migração.
- **Quota e chamadas externas:** YouTube `search.list` = 100 chamadas/dia (bucket próprio); passe por `lib/youtube/service.ts` ou `lib/youtube/video-status.ts`. Twitch (800 pontos/min): passe por `lib/twitch/service.ts` ou `lib/twitch/status.ts`; busca de 1 página por padrão (`TWITCH_MAX_PAGES`), cache de 180 s + 600 s (o Developer Agreement permite no máximo 24 h). Kick (sem limite documentado; `429` com `Retry-After`): passe por `lib/kick/service.ts` ou `lib/kick/status.ts`; a API v2 devolve da live mais antiga para a mais nova, então a busca segue o cursor, ordena por espectadores e corta nas 100 maiores; cache de 180 s + 600 s (termos: até 24 h; proibido redistribuir os dados).
- UI diz "Lives encontradas", nunca "todas". `concurrentViewers` ausente = `null` ("Não informado"). Selo "Conteúdo adulto" segue a regra do PRD D6 (`MatureGame` sozinho não conta); na Kick nunca aparece (D-K1, spec 020). Idade mínima do site: 16 anos (spec 052).
- Player: só o oficial de cada plataforma, sem autoplay, depois do consentimento, sempre com o link "Abrir no/na <plataforma>". A Twitch exige `parent` = hostname e área mínima de 400×300; o player dela pede login para GTA 6 (`MatureGame`), por isso o aviso da spec 044. A Kick (`player.kick.com/<slug>`) não pede login nem tamanho mínimo; nada pode cobrir o player (termos da Kick). Ao fechar, o foco é devolvido na hora, sem esperar o evento `close` (spec 055).
- Identidade visual própria; não usar logos, fontes, arte ou screenshots oficiais. Selo de plataforma é só texto.
- Logs do servidor só via `lib/telemetry.ts` (`logEvent`); nunca IP, chave, token ou URL do YouTube. Os logs de runtime da Vercel duram ~1 h: verificações de monitoramento são pontuais.
- Cores: `lib/config/design-tokens.ts` e `app/globals.css` precisam bater (teste `tests/contrast.test.ts`). Controles usam `border-strong`. O site só tem tema escuro.
- Textos de `/privacy` e `/terms` devem refletir o que o código faz; atualize-os ao mudar coleta de dados ou integrações (ex.: uma nova plataforma).
- Vercel CLI 59.x: `vercel env rm <nome> <ambiente>` apagou a variável de **todos** os ambientes (ocorrido em 2026-11-21). Para mudar ambientes de uma variável, use o painel. `vercel link` também baixa variáveis para `.env.local` e altera o `.gitignore`: confira com `git diff` depois. `YOUTUBE_API_KEY` existe só em Production: no Preview, o YouTube aparece como indisponível.
- Commits: Conventional Commits em pt-BR (ex.: `feat(cache): adiciona cache compartilhado no Upstash`), **sem** linha `Co-Authored-By`. Pedido do usuário em 2026-11-21.
- CSP aplicada em `next.config.ts` (spec 017): `img-src` com `i.ytimg.com`, `static-cdn.jtvnw.net`, `images.kick.com` e `web.kick.com`; `frame-src` com `www.youtube.com`, `player.twitch.tv` e `player.kick.com`; `connect-src 'self'` (APIs externas só no servidor). Nova origem externa precisa entrar nela. `npm run test:e2e` (Playwright, spec 014) falha em qualquer violação; rode-o ao mexer em UI, player ou cabeçalhos.
- Testes nunca chamam APIs reais: use fixtures (`tests/fixtures/`) ou `fetch` interceptado; o e2e simula `/api/*`, miniaturas e players.
- Trabalho pendente: issues do épico #28 e `sprint.md`; cada tarefa usa a branch `sprint/<id>` e só altera os arquivos listados.
